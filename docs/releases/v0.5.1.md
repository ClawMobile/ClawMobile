# ClawMobile v0.5.1 — Android 0.2.4 Beta Testing

ClawMobile v0.5.1 publishes the Android 0.2.4 (`versionCode 11`) test build and
adds a documented invitation-based ClawMobile Beta onboarding path.

## Highlights

- Hardens Android UI-skill recording and replay.
- Adds structured multi-step UI execution, transport, failure, recovery, and
  action-verification evidence.
- Lets stable Note and Maps workflows use fast paths while conservatively
  falling back for ambiguous dynamic-list controls.
- Adds public Android beta testing, invitation, quota, expiry, optional
  Accessibility/ADB, and safe issue-reporting guidance.
- Keeps Termux/OpenClaw available as the optional Shell Runtime.
- Does not include the deferred Feedback settings feature.

## Beta Access

ClawMobile Beta requires an individually issued, single-use invitation code.
Apply through the
[ClawMobile waitlist](https://clawmobile.ae/#waitlist), then follow the
[Android beta testing guide](../android-beta-testing.md).

Invitation codes are distributed privately. Do not request or share a code in a
public GitHub issue.

## Setup Notes

- The app-local runtime is the recommended default and does not require Termux.
- Accessibility is recommended for visible UI context, screenshots, OCR,
  phone actions, and demo recording.
- Built-in ADB is an optional enhancement for supported low-level actions.
- Termux/OpenClaw remains available for advanced Shell Runtime workflows.
- A debug-signed APK may need to be uninstalled before installing this
  release-signed build; uninstalling clears local app data.

## Known Limitations

- Generated Skills work best on the device, app version, layout, and starting
  state used for recording.
- Dynamic lists and repeated labels may fall back to normal model-guided UI
  execution. Some YouTube `Action menu` workflows intentionally do so.
- ADB may need to be re-enabled after a phone reboot.
- Invitation access can expire or reach its monthly request limit.
